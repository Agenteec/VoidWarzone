# Void Warzone — Техническое задание v0.2

## 1. Общее

| | |
|---|---|
| Жанр | Упрощённая RTS + кооп-защита (Hero of the Empire / Hero Defense), io-подача |
| Платформы | Windows, Linux, Android |
| Графика | Минималистичное 3D, камера сверху под углом; геймплей плоский (2D) |
| Сеть | Авторитарный сервер: выделенный или хост-игрок; P2P через NAT как в Steam |
| Игроков | Лимит задаёт хост (до 64) |
| Язык | C++20, всё включая мастер-сервер |

Основной режим разработки — **Защита (Void Siege)**.

Отказались:
- **raylib** — мало для 3D с инстансингом и своим пайплайном шейдеров.
- **Godot / Unreal** — свой движок даёт полный контроль над сервером и сетью.
- **GameNetworkingSockets (Steam)** — тянет protobuf, OpenSSL и WebRTC, плохо собирается под Android.
- **ENet** — сам владеет сокетом, его сложно пустить поверх ICE. Нет избыточной отправки команд.
- **Lockstep** (как в Warzone 2100 и SC2) — см. 3.2.

## 3. Архитектура

```
src/core    — симуляция: ECS, правила, карта, пути, бой, режимы. Общая для сервера и клиента.
src/net     — транспорт, каналы, снапшоты, ICE.
src/server  — headless-сервер. Также встраивается в клиент как listen server.
src/client  — рендер, UI, ввод, интерполяция, предсказание.
src/master  — мастер-сервер: лобби, сигналинг ICE, STUN/TURN, статистика, сохранения.
android/    — Gradle-проект (M6).
data/       — JSON: юниты, умения, предметы, волны, карты.
```

### 3.1. Разделение ответственности
- **Сервер** — простая 2D-модель: позиции (круги на сетке), HP, кулдауны, баффы, цели, попадания. Он единственный решает исход.
- **Клиент** — 3D-визуал, анимации, частицы, косметическая физика. Также запускает тот же `core` для предсказания своих юнитов.
- Физика и попадания на клиенте не считаются: это приведёт к расхождениям и даст простор для читов.

### 3.2. Сетевая модель
**Авторитарный сервер + предсказание на клиенте + интерполяция + визуал по событиям.** Это модель Dota 2 и LoL, а не lockstep из RTS.

Почему не lockstep: задержка ввода равна худшему пингу в игре; с 64 игроками один лагающий тормозит всех. Нельзя зайти в идущий матч. Нужен строгий детерминизм (fixed-point), а любая рассинхронизация ломает матч.

Откуда берётся задержка и что с ней делаем:

| Источник | Мера |
|---|---|
| Сетевой путь | Прямой P2P через ICE; relay только как запасной вариант; у хоста задержка 0 |
| Ожидание тика | Сервер 30 Гц; команда применяется в ближайший тик, без накопления |
| Отправка ввода | Команда уходит сразу, не ждёт кадра или тика |
| Потери пакетов | Каждый пакет ввода повторяет все неподтверждённые команды — без ожидания ретрансмита |
| Head-of-line blocking | Раздельные каналы: снапшоты ненадёжные и никогда не ждут надёжных |
| Буфер интерполяции | Адаптивный: ~1 тик + джиттер (40–60 мс вместо фиксированных 100 мс) |
| Отклик своих юнитов | Предсказание: юнит сразу начинает движение/атаку/каст; при расхождении — плавная коррекция, а не рывок |
| Снаряды | Сервер шлёт событие (тик, откуда, куда, скорость); клиент сам рисует полёт, сервер присылает только попадание |
| Крипы на линиях | Dead reckoning по flow field: клиент двигает сам, сервер шлёт поправки |

Трафик (64 игрока, тысячи юнитов):
- Дельта к последнему подтверждённому снапшоту.
- Квантование: позиция 16 бит на ось, угол 8 бит, HP в процентах.
- Interest management: игрок получает только то, что видит (туман войны).
- Priority accumulator: дальние и неважные объекты обновляются реже.
- Пакет ≤ 1200 байт, без IP-фрагментации.
- Цель: ≤ 30 КБ/с на игрока.

### 3.3. Пути и движение
- Сетка проходимости, высоты чисто визуальные.
- Крипы — flow field к цели линии. Юниты игроков — A* + сглаживание + разделение (boids).
- Всё в `core`, чтобы клиент мог предсказывать.

### 3.4. Данные
Юниты, оружие, умения, баффы, предметы, исследования, волны, боссы, карты — в JSON. Сервер передаёт хеш данных; при несовпадении подключение отклоняется.

## 4. Режимы

### 4.1. Защита — Void Siege (приоритет)
- **4 линии**, как в оригинале; база игроков против портала Пустоты.
- Готовая база: ядро (проигрыш при уничтожении), казармы на каждой линии, башни, стены, слоты под постройки.
- Союзные крипы из казарм; улучшение казарм усиливает волны.
- Волны ИИ по линиям, босс каждые N волн. Между волнами — пауза на покупки.
- Ресурсные точки захватываются стоянием в зоне; ИИ пытается их отбить.
- Победа — убить финального босса. Отдельно — бесконечный режим.
- Сложности: Лёгкая / Нормальная / Тяжёлая / Кошмар.
- Лимит игроков задаёт хост (до 64); сложность масштабируется от числа игроков.

### 4.2. Схватка — Warzone
- Закрытые команды.
- Исследования раздельные или общие (флаг режима).
- Ресурсные точки, строительство, боты.

## 5. Системы

### 5.1. Ресурсы
- **Энергия** — с точек и ядра.
- **Осколки Пустоты** — с боссов и элитных мобов, тратятся на героев и предметы.

### 5.2. Юниты и герои
Фиксированные типы юнитов (без конструктора). Любой юнит растёт по рангам:

| Ранг | Условие | Даёт |
|---|---|---|
| Рядовой | — | — |
| Ветеран | опыт | +статы |
| Элита | опыт + энергия | +статы, 1 слот, 1 пассивка |
| **Герой** | опыт + осколки, лимит на игрока | уровни, очки навыков, 6 слотов артефактов, 4 активных умения |

- Набор умений зависит от типа юнита плюс общие ветки.
- Умения собираются из примитивов (снаряд, область, бафф, призыв, рывок, аура) — новые добавляются данными.
- Артефакты: редкость, уникальные эффекты, комплекты.

### 5.3. Сохранения (как на картах Warcraft)
- Карта сама объявляет, что сохраняется (тип героя, уровень, предметы…).
- Хранение на мастер-сервере по игроку и карте; офлайн — сейв-код с подписью.
- Игрок идентифицируется ключом, созданным локально, без регистрации.
- Глобальной прокачки между матчами нет.

### 5.4. Статистика
Мастер-сервер хранит статистику игрока: матчи, победы, волны, убийства, боссы.

### 5.5. Исследования, постройки, ИИ
Как в v0.1: дерево исследований (общее или раздельное), башни, казармы, лавка, мастерская героев; волны и боссы описываются в данных, у боссов — фазы.

## 6. Подключение

1. LAN — автопоиск.
2. IP:порт.
3. **Комната по коду** (`VOID-7K3F`) — основной способ, как в Steam / Hamachi / Radmin.
4. Выделенный сервер.

Как работает комната:
1. Хост регистрирует комнату на мастер-сервере (Linux VPS в Германии).
2. Клиент запрашивает комнату по коду; мастер обменивает ICE-кандидатов между хостом и клиентом.
3. libjuice пробивает NAT (STUN на мастере), и устанавливается прямое UDP-соединение.
4. Если не удалось (симметричный NAT) — TURN-relay на мастере.
5. Поверх — наш транспорт: reliable + каналы.

## 7. Управление
- **ПК**: ЛКМ / рамка / Ctrl+цифра для выделения; ПКМ — приказ; WASD и края экрана, колесо — камера; умения на QWER.
- **Android**: тап, рамка удержанием, кнопки групп; перетаскивание и щипок для камеры; кнопки умений.

## 8. Производительность
- ПК: 60 FPS на встроенной графике.
- Android: 60 FPS на среднем устройстве 2021+, minSdk 26.
- Сервер: 30 Гц при 64 игроках и 2000+ юнитов.
